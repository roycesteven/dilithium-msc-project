Slide 1 · the picture

One signature scheme, four extra operations

LAS reuses the basic signature's KeyGen and Verify unchanged and adds an adaptor layer. The only algebraic change: the statement Y is folded into the Fiat–Shamir hash. Where is Y set up? In its own relation_gen step — not in KeyGen, not inside Sign.

LAS adaptor path

answers Wang's question
PreSign · las_presign
c = H( pk, w + Y, M ) · ẑ = y + c·r
reject at the tighter bound γ−κ−1
PreVerify · las_preverify
accept iff c̃ = H( pk, w' + Y, M )
Adapt · las_adapt  ·  Ext · las_ext
z = ẑ + y → ordinary Verify passes · y = z − ẑ recovers the witness
The one identity: Sign hashes w; PreSign hashes w + Y. Adapt adds the ternary witness y (‖y‖∞ ≤ 1), so A·z − c·t = (A·ẑ − c·t) + A·y = w' + Y ✓ — the adapted signature is a fully ordinary one. Publishing it leaks y = z − ẑ, which is exactly what makes an atomic swap atomic.

Slide 2 · the evidence

Correct, cross-validated, and nearly free

At matched parameters on shared primitives, the adaptor layer costs only a few percent of compute per operation, and does not enlarge the signature — its one extra object on the wire is the statement Y. Two independent implementations (C and Rust) produce byte-identical objects — the evidence that they are the same scheme.

Adaptor overhead (C reference) ≤9% → ≤80% core / struct API (pure adaptor math): PreSign +1.6% · PreVerify +5.1% · Adapt +9.0%. Full protocol incl. pack/unpack: +20.8% · +35.3% · +79.5% — the extra is decoding the pk-sized statement Y.
Communication overhead + statement Y one pk-sized object: 4416 B (65.7% of a signature). The signature itself does not grow — pre-signature = adapted = basic signature (6720 B); Adapt only adds the ternary y.
Rejection sampling — theory ⇔ measured ≈2.7× expected attempts (closed form): Sign 2.719 · PreSign 2.775 (tighter bound γ−κ−1). Measured over ≈10⁵ calls: 2.725 · 2.777. Every run gated at 5σ — the sample-size validity check.
