Why a chain cannot wait for the machine

  • The record is permanent. Every signature and every revealed public key stays readable forever — a break applies retroactively to coins already sitting under exposed keys.
  • Changing it is a consensus change, coordinated across a whole network — years, not a software update.

If you build Bitcoin

Carriage is not the problem. Verification is a consensus rule, not engineering.

  • measured a stock Core {{btcNodeTag}} node already mines these spends — nonstandard to relay, but consensus-valid
  • measured add one rule and a whole two-leg swap settles, against {{btcLasControls}} negative controls
  • measured the rule costs {{btcLasVerifyUs}} µs per input — {{btcLasRatioSchnorr}}× a Schnorr check
  • levels unmatched, so that ratio overstates · the rule is unanalysed — what is missing is analysis, not code

If you build on the EVM

Deployable today, with almost no margin — and no protocol change.

  • measured a real client mined the whole claim in one transaction — {{gasOptCapPct}}% of the per-transaction cap
  • measured one set down, verification alone is charged {{gasDTwoCapPct}}%
  • derived at the largest set one transaction is exceeded — arithmetic, never a measured total
  • one signature instance, 32-byte message · feasibility is settled, cost is not

If you design the protocol

Budget bytes, not adaptor computation — and budget the proof first.

  • measured the adaptor layer adds at most +{{ovMaxAll}}% over the base signature
  • measured but its objects are ×{{clRatioSig}} the classical ones on the wire
  • measured and the proof takes {{cfgThreeProofPct}}% of a whole swap — not the signature
  • so the work is π and the statement Y — and a relation whose statement is small by construction

Every figure says which warrant it carries — measured (run {{benchRunId}}, paired and interleaved, rejection counted and gated to 5σ, C ⇆ Rust byte-identical on digest {{katDigestHead}}…{{katDigestTail}}), derived, or cited. Anything else is an open question, and is said to be one.
