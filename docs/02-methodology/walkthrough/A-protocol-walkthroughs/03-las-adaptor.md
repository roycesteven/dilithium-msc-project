# A/03 · How OUR LAS adaptor signature works

> **Our code:** `ref/las.c` (C) and `rust/fips204-las/src/las.rs` (Rust). This is
> the paper's **Algorithm 2**. It **reuses** the base signature's KeyGen / Sign /
> Verify unchanged, and **adds** four operations plus one hashing tweak.

Read [A/02](02-simplified-dilithium.md) first. LAS is that scheme **plus a
statement `Y` folded into the challenge hash**. The signing secret and the
verification stay bit-identical; the new machinery lets a *pre*-signature be
completed into a real signature in a way that leaks a secret witness.

Notation (paper Table 1 / §3): the statement is `Y = t′`, the witness is `y = r′`
(a second ternary secret), and a **pre-signature** is written `σ̂ = (c, ẑ)`.

---

## The key idea in one line

`Sign` hashes `H(pk, w, M)`. **`PreSign` hashes `H(pk, w + Y, M)`** — the
statement `Y` is added to the commitment *before hashing*. Everything else
follows from that one change.

---

## KeyGen — identical to the base scheme, and it also makes statements

> C: `las_keypair` ([las.c:109](../../../../ref/las.c#L109)) ·
> Rust: `las_keypair` ([las.rs:213](../../../../rust/fips204-las/src/las.rs#L213))

Exactly the base KeyGen: `r ← S₁^{n+ℓ}`, `t = A·r`, `(pk, sk) = (t, r)`.

The **statement/witness pair `(Y, y)` is generated by the *same* function**:
`y ← S₁^{n+ℓ}`, `Y = A·y`. So a statement is literally just another public key,
and a witness is another secret key. Nothing new to implement — the paper's
`Gen` "runs exactly as KeyGen".

---

## Sign / Verify — reused verbatim

> `las_signature` ([las.c:214](../../../../ref/las.c#L214)),
> `las_verify` ([las.c:303](../../../../ref/las.c#L303))

These are the base signature's Sign/Verify (`c = H(pk, w, M)`), byte-for-byte.
Proof that they really are the same scheme: an **adapted** LAS signature (below)
verifies under the *independent* base verifier `base_sign_verify` — a test the
benchmark asserts on every run.

---

## PreSign — a pre-signature bound to a statement Y

> C: `las_presign_internal` via `las_presign` ([las.c:327](../../../../ref/las.c#L327)) ·
> Rust: `las_presign_internal` ([las.rs:376](../../../../rust/fips204-las/src/las.rs#L376))

Identical to Sign except the **two highlighted lines**:

```
   once per call:   ŝ = NTT(r)
   repeat:
     1.  y ← mask in S_γ^{n+ℓ}
     2.  w = A · y
     ┌── 3.  commit = w + Y                              ← ADD the statement
     └── 4.  c = H( pk , w + Y , M )                     ← hash the offset commitment
     5.  ẑ = y + c · r
     ┌── 6.  if ‖ẑ‖∞ > γ − κ − 1 :  restart             ← bound tightened by ONE
     └──
   return σ̂ = (c, ẑ)
```

- **Line 3–4:** the statement `Y` is added to the commitment before it is hashed
  (`las.c` builds `wY[j] = w[j] + Y->t[j]`, then hashes that).
- **Line 6:** the rejection bound is `γ − κ − **1**`, one tighter than Sign's
  `γ − κ`. This single unit of slack is reserved for the witness that `Adapt`
  will add. See "why the −1" below — it is *the* subtle point of the whole
  construction.

---

## PreVerify — check a pre-signature against Y

> C: `las_preverify_internal` via `las_preverify` ([las.c:433](../../../../ref/las.c#L433)) ·
> Rust: `las_preverify_internal` ([las.rs:463](../../../../rust/fips204-las/src/las.rs#L463))

```
   1.  if ‖ẑ‖∞ > γ − κ − 1 :  reject
   2.  w′ = A · ẑ − c · t
   3.  accept  iff  c == H( pk , w′ + Y , M )           ← re-apply the +Y offset
```

Same shape as base Verify, with the statement `Y` added back in at the hash
(step 3), matching what PreSign did.

---

## Adapt — complete a pre-signature into a real signature

> C: `las_adapt` ([las.c:548](../../../../ref/las.c#L548)) ·
> Rust: `las_adapt` ([las.rs:516](../../../../rust/fips204-las/src/las.rs#L516))

```
   1.  PreVerify(Y, pk, σ̂, M)   — abort if it fails
   2.  z = ẑ + y                 (add the witness to the response)
   3.  return σ = (c, z)
```

The output `σ = (c, z)` is an **ordinary signature** — same shape as base Sign's
output — and it passes the **ordinary** `Verify` with no mention of `Y`. Why:

```
   A·z − c·t = A·(ẑ + y) − c·t = (A·ẑ − c·t) + A·y = w′ + Y
```

and `w′ + Y` is exactly what the challenge `c` committed to in PreSign. So the
ordinary verifier recomputes the right commitment and accepts.

### Why the −1 bound (the one subtle point)

The witness is ternary, so `‖y‖∞ ≤ 1`. After `Adapt`,
`‖z‖∞ = ‖ẑ + y‖∞ ≤ ‖ẑ‖∞ + 1`. Because PreSign guaranteed `‖ẑ‖∞ ≤ γ − κ − 1`,
we get `‖z‖∞ ≤ (γ − κ − 1) + 1 = γ − κ` — landing **exactly** on ordinary
Verify's bound (paper Lemma 1, Eq. 1). If PreSign had used the looser `γ − κ`,
the adapted `z` could reach `γ − κ + 1` and **Verify would reject every adapted
signature**. That is the single failure mode of the construction, and the −1 is
what prevents it.

## Ext — recover the witness from the two signatures

> C: `las_ext` ([las.c:585](../../../../ref/las.c#L585)) ·
> Rust: `las_ext` ([las.rs:547](../../../../rust/fips204-las/src/las.rs#L547))

```
   1.  s = z − ẑ                (subtract the two responses)
   2.  return s   iff   A · s == Y      (else ⊥)
```

Because `z = ẑ + y`, the subtraction gives back **exactly** `s = y`, the witness.
This exactness is only possible because nothing is compressed — `z` and `ẑ` are
full-precision values. This is the mechanism that makes an atomic swap atomic:
publishing the adapted `σ` on-chain lets anyone who holds `σ̂` compute
`y = z − ẑ` and unlock the matching half of the swap.

## The seven operations at a glance

| Operation | Hash used | Bound | New vs base? |
|---|---|---|---|
| KeyGen | — | — | reused (also makes `(Y,y)`) |
| Sign | `H(pk, w, M)` | ‖z‖∞ ≤ γ−κ | reused verbatim |
| Verify | `H(pk, w′, M)` | ‖z‖∞ ≤ γ−κ | reused verbatim |
| **PreSign** | `H(pk, w+Y, M)` | ‖ẑ‖∞ ≤ γ−κ−1 | **new** |
| **PreVerify** | `H(pk, w′+Y, M)` | ‖ẑ‖∞ ≤ γ−κ−1 | **new** |
| **Adapt** | (calls PreVerify) | produces ‖z‖∞ ≤ γ−κ | **new** |
| **Ext** | — | — | **new** |
